# Archaeology: Historical Repository Archive

**Purpose**: Preserve historical files, completed work, and superseded documents while keeping the active repository clean and navigable.

**Philosophy**: "Does It Spark Joy?" - Active work stays visible, historical work moves to archaeology.

---

## Structure

### `docs/kernel/session_summaries/`
Session summaries from kernel development work. Historical records of completed sessions.

### `docs/agent-communications/2025-archive/`
Agent communication files from 2025 (older than 2 weeks from current date). Historical coordination records.

### `docs/legacy_prompts/`
Superseded agent prompts. Historical prompts that have been replaced by newer versions.

### `docs/legacy_coordination/`
Completed coordination work. Historical coordination documents that have been superseded.

---

## Archive Criteria

**Files are archived when**:
- They are older than 2-3 weeks (for agent communications)
- They represent completed work (session summaries)
- They have been superseded by newer versions (prompts, coordination)
- They have historical value but are not actively referenced

**Files stay active when**:
- They are from the last 2-3 weeks
- They are actively referenced
- They represent current work
- They are foundational documents (grain_style.md, gratitude.md, etc.)

---

## Access

All archived files remain in git history and can be accessed via:
- Direct file path
- Git history
- Search tools
